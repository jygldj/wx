### 1.3 lunar.js 关键 API 速查

本底稿所有功能之数据源，均取自 `lunar.js`。经逐行勘察，确认以下方法可用：

**干支推算**（应期反查之基石）：
- `Solar.fromYmd(y, m, d).getLunar().getDayInGanZhi()` — 取任意公历日之日柱干支
- `lunar.getMonthInGanZhiExact()` — 取月柱干支（按节气精确交割）
- `lunar.getYearInGanZhiExact()` — 取年柱干支（按立春精确交割）
- `lunar.getMonthZhi()` — 取月建地支（如"寅"）

**黄历通书**（黄历通书之基石）：
- `lunar.getDayYi()` / `lunar.getDayJi()` — 当日宜/忌，返回 `string[]`
- `lunar.getDayJiShen()` / `lunar.getDayXiongSha()` — 当日吉神/凶煞，返回 `string[]`
- `lunar.getDayChong()` / `lunar.getDayChongDesc()` / `lunar.getDaySha()` — 当日冲煞（冲某/煞某方）
- `lunar.getXiu()` / `lunar.getXiuLuck()` / `lunar.getXiuSong()` — 二十八宿宿名/吉凶/歌诀
- `lunar.getZheng()` / `lunar.getAnimal()` / `lunar.getGong()` / `lunar.getShou()` — 值神星君/宿动物/四象宫/守护神
- `lunar.getPengZuGan()` / `lunar.getPengZuZhi()` — 彭祖百忌（天干/地支两部分）
- `lunar.getDayNaYin()` — 纳音
- `lunar.getYearShengXiao()` / `lunar.getDayShengXiao()` — 生肖

**方位神煞**：
- `lunar.getDayPositionXi()` / `getDayPositionXiDesc()` — 喜神方位
- `lunar.getDayPositionCai()` / `getDayPositionCaiDesc()` — 财神方位
- `lunar.getDayPositionFu()` / `getDayPositionFuDesc()` — 福神方位
- `lunar.getDayPositionYangGui()` / `getDayPositionYinGui()` — 阳贵/阴贵神方位
- `lunar.getDayPositionTaiSui()` / `getDayPositionTaiSuiDesc()` — 太岁方位

**节气**：
- `lunar.getPrevJieQi(wholeDay)` / `lunar.getNextJieQi(wholeDay)` — 前后节气，返回 `{getName(), getSolar(), isJie(), isQi()}`
- `lunar.getJieQiTable()` — 全年24节气表 `{name: Solar}`
- `lunar.getCurrentJieQi()` — 当日是否为节气日

**时辰级**（真太阳时起卦之辅助）：
- `lunar.getTimeInGanZhi()` — 时柱干支
- `lunar.getTimeYi()` / `lunar.getTimeJi()` — 时辰宜忌
- `lunar.getTimeChong()` / `lunar.getTimeSha()` — 时辰冲煞

**重要缺口**：lunar.js **未实现** 十二建除（建/除/满/平/定/执/破/危/成/收/开/闭）。此功能需在通鉴页自行实现（见 4.4 节）。

### 1.4 现有数据流经脉

经勘察，现有三页之间数据传递路径如下：

```
jiegou.html ──[localStorage.currentGua + localStorage.gua_<id>]──> jiegua.html?id=<id>
     │                                                                    │
     │ <── sessionStorage.currentGua（兜底）──                              │
     │                                                                    │
     └──[localStorage.wnlResult]<── wnl.html（当前无交互，独立运行）          │
                                                                          │
                    jiegua.html timeInfo: {solarTime, lunarTime, yueJian, riChen, xunKong} ←─┘
```

当前 `wnl.html` 与 `jiegou.html`/`jiegua.html` 之间**无数据交互**——`wnl.html` 仅将结果存入 `localStorage.wnlResult`，但 `jiegou.html` 和 `jiegua.html` 均未读取该字段。天时通鉴之核心使命，即打通此经脉。

## 二、应期反查（必杀技）

### 2.1 场景

释卦页（`jiegua.html`）AI 解读中常出现"应期在寅月寅日"之类断语。用户需知：未来哪些公历日期符合此干支条件，距今多久。

### 2.2 入口设计

在 `jiegua.html` 的解读结果区，为每段含"寅月寅日""午月卯日"等应期表述的文本，附加"查干支对应公历"按钮。点击后携带参数跳入 `wnl.html`。

**参数传递方案（铁律：严禁 JSON 塞 URL）**：

采用精简 URL 参数方案。URL 格式：

```
wnl.html?yingqi=寅月寅日
```

参数编码规则：
- `yingqi` 值格式为 `<月建地支>月<日柱地支>日`，如 `寅月寅日`、`午月卯日`
- 仅传地支，不传天干——因应期推断以地支（逢填实、逢冲、逢合）为主，天干非关键
- 如需传完整干支（月柱+日柱），格式为 `寅月甲寅日`（日柱带天干），通鉴页解析时容错处理
- 特殊场景：`yingqi=寅月`（仅月建，无日支）→ 高亮整个月
- 特殊场景：`yingqi=寅日`（仅日支，无月建）→ 高亮全月所有匹配日支之日期

**为何不用 localStorage 传参**：应期反查是 URL 可分享、可收藏的场景，localStorage 无法传递给他人。URL 精简参数既满足分享需求，又避免 JSON 塞 URL 之弊。

### 2.3 通鉴页解析与高亮逻辑

通鉴页加载时执行以下流程：

**步骤一：URL 参数解析**

```
1. 读取 location.search，解析 yingqi 参数
2. 正则匹配：/^([子丑寅卯辰巳午未申酉戌亥])月(([子丑寅卯辰巳午未申酉戌亥])日)?$/
3. 提取 yueZhi（月建地支）和 riZhi（日柱地支，可为空）
4. 若格式不合法，显示提示"应期参数格式无法识别"，不执行反查
```

**步骤二：确定扫描范围**

- 默认扫描：当前公历日起，向后扫描 365 天（覆盖一个完整干支年周期，确保不遗漏）
- 可扩展：用户可手动调整扫描范围（前推/后推天数）

**步骤三：逐日匹配**

对扫描范围内每一公历日，执行：

```
1. solar = Solar.fromYmd(y, m, d)
2. lunar = solar.getLunar()
3. monthZhi = lunar.getMonthZhiExact()   // 按节气精确取月建地支
4. dayZhi   = lunar.getDayInGanZhi().charAt(1)  // 取日柱地支
5. 匹配规则：
   - 若 yingqi 含月+日：monthZhi === yueZhi && dayZhi === riZhi → 完全匹配
   - 若 yingqi 仅含月：monthZhi === yueZhi → 月建匹配（高亮整月所有日期）
   - 若 yingqi 仅含日：dayZhi === riZhi → 日支匹配（高亮所有匹配日支之日期）
```

**关键技术点**：月建必须用 `getMonthZhiExact()`（按节气精确交割），而非 `getMonthZhi()`（按月粗分）。因"寅月"指立春至惊蛰之间，非农历正月。lunar.js 的 `getMonthZhiExact()` 已封装此逻辑，必须使用。注意：lunar.js 月建以立春**次日**为界（非当日），系统口径以此为准。

**步骤四：结果展示**

在日历网格上，对匹配日期施加高亮样式（如背景色标注、边框加粗）。日历下方列出匹配结果列表：

```
应期：寅月寅日
━━━━━━━━━━━━━━━━━━━━━━━━━━
序号  公历日期         星期   农历      月建  日柱  距今
 1    2026-02-18      三    正月初二   寅    甲寅  +196天
 2    2026-03-06      五    正月十八   寅    丙寅  +212天
 ...
━━━━━━━━━━━━━━━━━━━━━━━━━━
```

"距今"计算：以当前公历日 00:00 为基准，计算目标公历日与基准之日历天数差（不含时分秒，仅日级精度）。

**步骤五：日历视图联动**

通鉴页的日历视图需支持：
- 月份翻页（上一月/下一月/回到今日）
- 匹配日期在日历网格中以醒目标记标注
- 点击匹配日期，右侧黄历栏同步显示当日通书（见第四章黄历通书）

### 2.4 容错与边界

- `yingqi` 参数缺失或格式不合法：通鉴页正常加载，不执行反查，显示默认日历视图
- 扫描范围内无匹配：显示"365天内未找到符合 `{yingqi}` 之日期，可尝试扩大搜索范围"
- 跨年场景：如当前为申月，查"寅月寅日"，可能需跨越至次年——365天扫描已覆盖
- 月建边界：lunar.js 月建以立春**次日**为界（非当日），如立春 2/4 当日月建仍为丑，2/5 方入寅月。系统统一用此口径，内部自洽

## 三、真太阳时起卦（回马枪）

### 3.1 场景

用户在通鉴页选定日期、输入时间、自动定位（或手动输入经度）后，通鉴页计算出真太阳时。用户点击"以此时间起卦"，将时间参数传递回 `jiegou.html`，直接进入起卦流程。

### 3.2 现有真太阳时计算

`wnl.html` 已实现真太阳时计算（`trueSolarTime` 函数，第 353-377 行），算法如下：

1. 以北京时间为基准（`h:mi`）
2. 经度校正：`lonCorr = (lng - 120) * 4`（分钟，东加西减）
3. 均时差：`equationOfTime(dayOfYear)`（基于地球轨道偏心率和黄赤交角的近似公式）
4. 真太阳时（分钟）= 北京时间分钟 + 经度校正 + 均时差

此算法已验证可用，通鉴页直接复用，不另起炉灶。

### 3.3 传参方案

**方案：localStorage 主传 + URL 精简参数辅助**

通鉴页"以此时间起卦"按钮点击后：

**第一步：组装 timeInfo 对象**

```javascript
var timeInfo = {
    solarTime: '2026年8月6日 星期四 14:30',  // 公历时间描述
    lunarTime: '丙午年 七月十四',              // 农历时间描述
    yueJian: '未',                              // 月建地支
    riChen: '壬子',                             // 日柱干支（完整，非仅地支）
    xunKong: '寅卯',                            // 旬空
    shiChen: '未',                              // 时辰地支
    // 以下为通鉴新增字段，供 jiegou.html 直接使用
    solarYmd: '2026-08-06',                     // 公历 YYYY-MM-DD（新增）
    zhenSunTime: '14:23:17',                    // 真太阳时 HH:MM:SS（新增）
    longitude: 116.41,                          // 经度（新增）
    placeName: '北京（GPS）'                     // 地点名（新增）
};
```

**第二步：存入 localStorage**

```javascript
localStorage.setItem('tstj_timeInfo', JSON.stringify(timeInfo));
```

**第三步：跳转 jiegou.html**

```javascript
location.href = 'jiegou.html?from=tstj';
```

URL 仅携带 `from=tstj` 标识，不传任何业务数据。`jiegou.html` 加载时检测此标识，从 `localStorage.tstj_timeInfo` 读取 timeInfo。

### 3.4 jiegou.html 接收逻辑

`jiegou.html` 的内联脚本区（第 97-316 行 IIFE）需新增以下逻辑：

**加载时检测 `from=tstj` 参数**：

```
1. 解析 location.search，检测 from=tstj
2. 若存在，从 localStorage.tstj_timeInfo 读取 timeInfo
3. 将 timeInfo 写入 localStorage.currentGua.timeInfo（如 currentGua 不存在则创建空壳）
4. 同步写入 sessionStorage.currentGua
5. 在手动输卦区的时间下拉框中预填 timeInfo 的值：
   - selYear 选中 timeInfo.riChen 的年柱（需从 timeInfo 推算或直接存入）
   - selMonth 选中 timeInfo.yueJian
   - selDay   选中 timeInfo.riChen
   - selHour  选中 timeInfo.shiChen
6. 切换到"手动输卦"模式（激活 modeInputBtn）
7. 显示提示"已从天时通鉴载入时间参数"
8. 消费后删除 localStorage.tstj_timeInfo（防止重复加载）
```

**与现有 applyManualTimeInfo 函数的衔接**：

现有 `applyManualTimeInfo()`（第 168-196 行）在排盘按钮点击时执行，将手动时间写入 `currentGua.timeInfo`。从通鉴页传入的 timeInfo 已包含完整字段，`applyManualTimeInfo()` 无需修改——它读取下拉框的值组装 timeInfo，而通鉴页已预填了这些下拉框。

但需注意：通鉴页传入的 `riChen` 是完整干支（如"壬子"），而 `applyManualTimeInfo` 的 `assembleTimeInfo` 函数将其直接存入。需确保 jiegou.html 的 `selDay` 下拉框使用六十甲子序列，`riChen` 值能在其中找到对应 option。

### 3.5 timeInfo 字段对齐

通鉴页传出的 timeInfo 与 `jiegua.html` 期望的 timeInfo 结构必须完全对齐。经勘察 `jiegua.html` 第 1024-1032 行和 `jiegou.html` 的 `assembleTimeInfo`，确认字段如下：

| 字段 | 类型 | 示例 | 用途 | jiegua.html 消费处 |
|------|------|------|------|-------------------|
| solarTime | string | "2026年8月6日 星期四 14:30" | 显示公历时间 | displayGuaInfo → #displaySolarTime |
| lunarTime | string | "丙午年 七月十四" | 显示农历时间 | displayGuaInfo → #displayLunarTime |
| yueJian | string | "未" | 月建地支，rw7 月破计算 | guaInfo.timeInfo.yueJian → jiSuanYuePo |
| riChen | string | "壬子" | 日柱干支，rw7 日破/旬空计算 | guaInfo.timeInfo.riChen → jiSuanRiPoAnDong |
| xunKong | string | "寅卯" | 旬空，rw7 真空假空计算 | guaInfo.timeInfo.xunKong → jiSuanZhenKongJiaKong |
| shiChen | string | "未" | 时辰地支（新增） | 时柱干支推算（五鼠遁） |

通鉴页新增字段 `solarYmd`、`zhenSunTime`、`longitude`、`placeName` 为可选增强信息，`jiegua.html` 若不消费这些字段亦不影响核心流程——它们只是存入 currentGua 供调试或未来扩展。

### 3.6 精度保障铁律

- 真太阳时计算精度到秒（`ztS = Math.round(...)` 已实现）
- 时辰划分：`(ztH+1)%24/2` 取整，23时和0时均归子时——与 `wnl.html` 现有逻辑一致
- 日柱始终取 `Solar.fromYmd(y,m,d).getLunar().getDayInGanZhi()`（不带时间，子时23-24归当天）——此为 `wnl.html` 铁律三（第577行注释明确）
- 年柱用 `getYearInGanZhiExact()`（立春精确）、月柱用 `getMonthInGanZhiExact()`（节气精确）——与 `wnl.html` render 函数一致

## 四、黄历通书（护身甲）

### 4.1 场景

用户在通鉴页日历中点击任意一日，右侧面板展示当日黄历全貌。

### 4.2 数据源（全部取自 lunar.js）

| 展示项 | lunar.js 方法 | 返回类型 | 说明 |
|--------|--------------|---------|------|
| 宜 | `lunar.getDayYi()` | `string[]` | 当日宜做的事项 |
| 忌 | `lunar.getDayJi()` | `string[]` | 当日忌做的事项 |
| 吉神宜趋 | `lunar.getDayJiShen()` | `string[]` | 吉神列表 |
| 凶煞宜避 | `lunar.getDayXiongSha()` | `string[]` | 凶煞列表 |
| 冲煞 | `lunar.getDayChong()` + `lunar.getDaySha()` | `string` + `string` | 冲某+煞某方 |
| 二十八宿 | `lunar.getXiu()` + `lunar.getXiuLuck()` + `lunar.getXiuSong()` | `string` × 3 | 宿名+吉凶+歌诀 |
| 值神星君 | `lunar.getZheng()` | `string` | 当日值神 |
| 彭祖百忌 | `lunar.getPengZuGan()` + `lunar.getPengZuZhi()` | `string` × 2 | 天干禁忌+地支禁忌 |
| 纳音 | `lunar.getDayNaYin()` | `string` | 日柱纳音 |
| 生肖 | `lunar.getDayShengXiao()` | `string` | 日生肖 |
| 喜神方位 | `lunar.getDayPositionXi()` + `getDayPositionXiDesc()` | `string` × 2 | 方位+描述 |
| 财神方位 | `lunar.getDayPositionCai()` + `getDayPositionCaiDesc()` | `string` × 2 | 方位+描述 |
| 福神方位 | `lunar.getDayPositionFu()` + `getDayPositionFuDesc()` | `string` × 2 | 方位+描述 |
| 阳贵神 | `lunar.getDayPositionYangGui()` + `getDayPositionYangGuiDesc()` | `string` × 2 | 方位+描述 |
| 阴贵神 | `lunar.getDayPositionYinGui()` + `getDayPositionYinGuiDesc()` | `string` × 2 | 方位+描述 |
| 太岁方位 | `lunar.getDayPositionTaiSui()` + `getDayPositionTaiSuiDesc()` | `string` × 2 | 方位+描述 |
| 节气 | `lunar.getCurrentJieQi()` / `getPrevJieQi()` / `getNextJieQi()` | `JieQi对象` | 当前/前后节气 |

### 4.3 铁律

- 数据源必须且仅取自 `ly/lunar.js`（或 `../lunar.js`，二者同源），严禁外链任何第三方 API
- 宜忌、吉神凶煞返回的是 `string[]`，展示时以逗号或分隔符连接
- `getDayYi()` / `getDayJi()` 可传 `sect` 参数（1=标准月柱，2=精确月柱），通鉴页默认传 1（与 lunar.js 默认值一致）

### 4.4 十二建除（自行实现）

lunar.js 未实现十二建除（建/除/满/平/定/执/破/危/成/收/开/闭），需在通鉴页自行实现。

**算法**：十二建除以月建地支为建，逐日按地支顺序排布。具体规则——

月建地支为"寅"（立春至惊蛰），则：
- 寅日为"建"，卯日为"除"，辰日为"满"，巳日为"平"，午日为"定"，未日为"执"
- 申日为"破"，酉日为"危"，戌日为"成"，亥日为"收"，子日为"开"，丑日为"闭"

通则：设月建地支在地支序（子0丑1寅2...亥11）中的索引为 `m`，当日地支索引为 `d`，则建除序号为 `(d - m + 12) % 12`，对应表为：

```
var JIAN_CHU = ['建','除','满','平','定','执','破','危','成','收','开','闭'];
var zhiIdx = ZHI.indexOf(dayZhi);
var monthIdx = ZHI.indexOf(monthZhi);
var jianChuIdx = (zhiIdx - monthIdx + 12) % 12;
var jianChu = JIAN_CHU[jianChuIdx];
```

此算法为通则，已验证与传统历书一致。但需注意：月建必须用 `getMonthZhiExact()`（节气精确），否则节气交割日当天建除会出错。

### 4.5 展示布局

右侧黄历面板建议分区展示：

- **第一区·干支总览**：四柱干支（年/月/日/时）+ 纳音 + 生肖 + 星期 + 农历
- **第二区·宜忌**：宜（绿色背景） / 忌（红色背景），条目以逗号分隔
- **第三区·神煞**：吉神宜趋（绿底）/ 凶煞宜避（灰底）
- **第四区·冲煞值神**：冲某煞某方 + 二十八宿宿名/吉凶/歌诀 + 值神星君

## 七、军师锦囊（考校与提点）

### 7.1 应期反查逻辑闭环校验

**校验点一：月建取法**

`getMonthZhi()` 返回的是农历月对应的地支（如农历正月=寅），而 `getMonthZhiExact()` 返回的是按节气精确交割的地支。应期推断中的"寅月"指立春至惊蛰之间，必须用 `getMonthZhiExact()`。

**重要更正（经云长将军实测）**：此前底稿误断"节气交割日当天 `getMonthZhiExact()` 返回新月建"。实测证实：lunar.js 实际以**立春次日**为月建切换点，非当日。如 2026 年立春为 2 月 4 日，`getMonthZhiExact()` 在 2 月 4 日当日仍返回"丑"，2 月 5 日方返回"寅"。

此非 lunar.js 之 bug——全站统一用此口径，系统内部自洽。但后续维护者须知晓此特性，避免误以为"漏了立春当天"。

通鉴页应期反查是日级扫描（按公历日，不含时分），统一以 `getMonthZhiExact()` 返回值为准。

**校验点二：365天扫描是否足够**

六十甲子周期为60天。月建以节气为界，一个节气月约30天。因此"寅月寅日"在最坏情况下，从当前日起扫描365天，必然覆盖至少一个完整的"寅月"时段（立春至惊蛰），且在该时段内至少出现2次"寅日"（30天/12≈2.5次）。365天扫描足够。

但若用户当前恰在寅月末（如惊蛰前一天），扫描365天会跳过当前寅月（因当前寅月已快结束），进入下一个寅月（约11个月后）。此时结果可能只有1-2个匹配日，且距今较远。这是正确行为——通鉴页如实展示，不做"补扫前推"（因应期是"未来"之期，非"过去"之期）。

**校验点三：URL 参数安全性**

`yingqi` 参数仅含汉字地支（子丑寅卯辰巳午未申酉戌亥）+ "月" + "日"字符，不含任何可执行代码。但通鉴页解析时仍需做格式校验（正则匹配），不合法则不执行反查，避免 XSS。

### 7.2 真太阳时回传逻辑闭环校验

**校验点一：timeInfo 字段完整性**

通鉴页传出的 timeInfo 必须包含 `jiegua.html` 期望的全部五个核心字段：`solarTime`、`lunarTime`、`yueJian`、`riChen`、`xunKong`。缺任何一个，`jiegua.html` 的 rw7 函数将无法正确计算月破/日破/旬空。

通鉴页组装 timeInfo 时，`yueJian` 取自 `lunar.getMonthZhiExact()`，`riChen` 取自 `lunar.getDayInGanZhi()`，`xunKong` 取自 `lunar.getDayXunKong()`——三者均直接调用 lunar.js，数据准确。

**校验点二：与 jiegou.html 手动输卦区的衔接**

`jiegou.html` 的 `selYear` 下拉框使用六十甲子序列（`jiaZi60()` 函数，第 111-115 行），`selDay` 同样使用六十甲子序列。通鉴页传出的 `riChen` 是完整干支（如"壬子"），能在六十甲子序列中找到对应 option。

但 `selYear` 应选中年柱干支，而非日柱干支。通鉴页需在 timeInfo 中额外存入年柱干支（`nianGanZhi` 字段），供 jiegou.html 预填 `selYear`。若不存入，jiegou.html 的 `getNowTimeInfo()` 兜底会取当前时间年柱——但通鉴页的时间可能是用户手动选定的历史/未来日期，年柱可能与当前不同。

**修正**：timeInfo 需新增 `nianGanZhi` 字段，取自 `lunar.getYearInGanZhiExact()`。

**校验点三：localStorage 生命周期**

`tstj_timeInfo` 在 jiegou.html 消费后删除（防止重复加载）。但若用户从通鉴页跳转 jiegou.html 后，又用浏览器"后退"回到通鉴页，再点击"以此时间起卦"再次跳转——此时 `tstj_timeInfo` 已被重新写入（通鉴页每次点击都重新组装并写入），不存在数据丢失。

### 7.3 黄历通书数据完整性校验

**校验点一：lunar.js 方法返回值验证**

`getDayYi()` 和 `getDayJi()` 返回 `string[]`，某些日期可能返回空数组（无宜或无忌）。通鉴页展示时需处理空数组——显示"无"而非空白。

`getDayJiShen()` 和 `getDayXiongSha()` 同理。

**校验点二：十二建除自实现正确性**

自实现的建除算法 `(zhiIdx - monthIdx + 12) % 12` 索引 `JIAN_CHU` 数组，需验证：

- 寅月寅日：`(2-2+12)%12 = 0` → "建" ✓
- 寅月卯日：`(3-2+12)%12 = 1` → "除" ✓
- 寅月丑日：`(1-2+12)%12 = 11` → "闭" ✓

已验证正确。但需注意月建用 `getMonthZhiExact()`，不可用 `getMonthZhi()`。

### 7.4 与现有架构的兼容性

**不动地基**：suanfa.js 排盘核心算法、zhukong.js 主控流程、lunar.js 时间计算核心逻辑——此三者铁律不改。通鉴页的所有新增功能均在 wnl.html 内部实现，不触碰 ly/ 四模块。

**jiegou.html 改动最小化**：仅在 IIFE 内新增 `from=tstj` 检测与预填逻辑，不改 zhukong.js 的 `completeAndDisplay`/`renderFinalResult`/`buildGuaHtml`。通鉴页传入的 timeInfo 经 `applyManualTimeInfo` 现有路径写入 `currentGua`，流程不变。

**jiegua.html 改动最小化**：新增"查干支对应公历"按钮仅为一个 `<a>` 或 `<button>` 元素，点击事件拼接 URL 跳转，不改动三级加载逻辑、不改动 AI 调用流程。
